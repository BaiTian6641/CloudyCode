# Design implementation mapping

## Token pipeline

`shared/design-system/tokens.json` is the canonical palette/metric source. The specimen stylesheet is generated by `tools/generate_design_tokens.py`; `tools/generate_android_tokens.py` now emits checked-in Android constants for colors, numeric typography, spacing, radii, density and motion. The implemented `CloudyTheme` maps a subset into Material color/type/shape roles for the real local-window apps. Complete role coverage, density behavior, shell geometry and renderer theme integration remain P1-S2 work; generated constants do not qualify components. See the [external feedback review](2026-10-16-external-feedback-review.md) for current mapping gaps. Do not maintain independent hand-edited palettes in two apps.

The token JSON includes paired contrast checks and fixed terminal ANSI colors. Native UI uses Material components with Cloudy wrappers; any Carbon reference token is mapped by role rather than imported as a global override. The [Compose M3 guide](https://developer.android.com/develop/ui/compose/designsystems/material3) is the implementation reference; exact selected versions and qualification boundaries are recorded in the [product toolchain](../03-platform/googlebook/product-toolchain.md).

## Surface map

| Product surface | Proposed implementation | Design responsibility |
| --- | --- | --- |
| Window shell/navigation | Compose + selected adaptive/window libraries | Current-window layout, focus, insets and instance state |
| Buttons/fields/dialogs/menus | M3 semantic components wrapped by Cloudy contracts | Roles, shape, density, keyboard and accessibility |
| Dense tables/tree | Native components/custom layout after semantics review | Alignment, selection, virtualization, readable metadata |
| Terminal | Isolated local renderer experiment in native host | ANSI palette, exact input/selection/resize; no general web browsing |
| Stream | Native decoder/surface/backend | Input capture and media lifecycle, no React/JSON frame path |
| RDP / VNC | Maintained native engine + common Desktop surface/input contract | Protocol-specific trust, negotiation, session semantics and diagnostics |
| X11 app windows | Native X server adapter + Android desktop window broker | Top-level/dialog ownership, host identity, native focus/IME/caption |
| Files/attachments | System picker, URI grants, native transfer UI | Clear source/destination and commit/conflict states |
| Console session files | Shared file models/transfer service + native adjacent pane + scoped export staging | Correct session binding, bidirectional drop and staged edits without Desktop dependency |
| Device status | Native ownership state machine view | Authority/unknown/protection semantics |
| Diagnostics | Native bounded structured views/export | Exact error, context, redaction and measurement provenance |

## What the specimen demonstrates

The offline specimen is original HTML/CSS/JavaScript. It is a review surface for the visual language and limited local interactions. It provides app selection, appearance/density changes, simulated connection states, inspector visibility, and a keyboard-operated command palette. All hosts, files, output, traffic, and progress are synthetic. The illustrative desktop scene is not a vendor screenshot or a working stream.

It deliberately does not establish Android IME, SSH, screen-reader terminal support, native video, pointer capture, cross-app IPC, backend launch APIs, or USB compatibility. The screen specification and stage gates remain the authority for those behaviors.

Revision 01's S13–S17 describe additional native desktop workflows. The specimen remains an initial visual-language artifact; it does not simulate those new clients/windows or establish phone/tablet support. The [desktop workflow design](desktop-workflows.md) binds the new flows to canonical roles and native semantics.

## P1 implementation sequence

1. Stabilize schema/version/names for tokens and map them to native roles; keep component geometry provisional until native review.
2. Implement shared shell and shared controls with semantic states and keyboard behavior.
3. Add current-window resize/caption/instance probes with guarded platform calls.
4. Port S02/S06 and the revised S13–S17 flows as native skeletons, using synthetic state models with explicit limits and qualified engine probes where available.
5. Run the [native workspace review](native-workspace-review.md) for text scale, both themes/densities, tiled windows, host context, input release, owned modals and permission interruptions on hardware. Freeze only demonstrated component behavior.
6. Bind real domain state only after its authority/failure semantics exist.

Keep reusable component APIs small. A button takes a semantic role/action/state, not arbitrary color overrides. File/USB/session components render typed states with required identity/context. Product copy should not expose implementation details unless they help the user recover or choose meaningfully.
