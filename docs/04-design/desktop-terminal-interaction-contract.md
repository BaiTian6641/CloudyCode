# Desktop terminal interaction contract

**Authority:** [Rule 0](../00-project/platform-rule-zero.md), the user's desktop interaction requirement, [Console C04/C05/C08/C18/C19](../01-product/console.md), and the existing [interaction rules](interaction.md). **State:** planned product acceptance contract; checked against official references on **2026-10-15** and amended **2026-10-16** by the [workspace home revision](2026-10-16-workspace-home-revision.md), which adopts the MobaXterm default terminal pointer model defined below. It does not qualify a renderer or introduce a phone/tablet workstream. The P0 diagnostic is a qualification surface, not the completed Console application.

Cloudy must provide ordinary desktop keyboard, mouse and trackpad workflows independently of the reused terminal engine. A library's default gesture or application shell does not define Cloudy's product interaction. Prefer adapting supported APIs over replacing a mature engine solely because its sample UI favors touch. Keep native IME, Android permissions, accessibility, user font scaling and lifecycle behavior intact.

## Focus and shortcut ownership

Keep one visible keyboard recipient per window. OS-reserved chords remain with the system; an active menu, modal or IME composition gets its valid keys before local shortcuts; deliberate Cloudy commands precede remaining terminal input. Hover does not change keyboard focus. A local action must execute once, with neither its keydown nor keyup leaking a second remote action. Do not implement a second native character-forwarding path alongside the renderer.

Display shortcuts in Edit/context menus and the command palette, and expose active shortcuts through the Android shortcut helper where available. A remapping UI must show conflicts, scope, the terminal meaning displaced, and a restore-defaults action. It cannot promise interception of OS-reserved keys. Keep a menu route when a chord is unavailable on the actual layout. AltGr, dead keys and composed input must not be mistaken for command modifiers. Android key events are not a substitute for committed IME text. [KeyEvent reference](https://developer.android.com/reference/android/view/KeyEvent), [Compose keyboard actions](https://developer.android.com/develop/ui/compose/touch-input/keyboard-input/commands).

The default terminal commands are Ctrl+Shift+C to copy a local selection and Ctrl+Shift+V to paste explicitly. Ctrl+C preserves terminal input, normally interpreted as interrupt by the remote PTY's current line discipline; Cloudy must not assert that every remote program will produce SIGINT. Ctrl+A, Ctrl+X, Ctrl+V and Ctrl+Z also retain their terminal meanings unless the user deliberately remaps them. Copy is read-only: it does not cut remote output or send a remote key.

Native profile/search/path/composer fields use ordinary editable-field semantics: Ctrl+C/X/V/A and undo Ctrl+Z where supported; redo is exposed with the component's qualified shortcut. Password/secret fields follow native privacy restrictions rather than guaranteeing that copying is available. Do not let a global terminal handler consume field editing. Use native selection/context menus and supported components first. [Compose built-in keyboard actions](https://developer.android.com/develop/ui/compose/touch-input/keyboard-input/commands).

## Pointer, menus and remote routing

Text supports direct mouse/trackpad drag selection, word/line selection and visible selection feedback. Under the default MobaXterm-style policy adopted on 2026-10-16, completing a pointer selection copies it immediately with visible feedback (copy-on-select never alters terminal content), and right-click performs the single explicit paste action. A persisted per-app setting switches right-click back to opening the local context menu; the menu keeps a Keyboard Menu/Shift+F10 or visible-menu-button route in both modes where qualified. Copy, Paste, Select all, Find and focus actions remain reachable without a long press. Touch long-press may supplement these routes on a touchscreen Googlebook; it cannot be their prerequisite.

While a remote terminal application requests mouse reports, show the active routing state and preserve a local selection override, initially Shift+drag as specified in [interaction.md](interaction.md). A remote-mouse policy may forward secondary-button reports, but must provide an explicit local-menu override and visible menu button. Each pointer event has one owner: opening a local menu must not also click remotely. Every paste route — right-click, Shift+Insert, Ctrl+Shift+V, Edit menu or context menu — performs the same single explicit action with the same paste safeguards; no route appends Enter, and a tab switch, disconnect or changed target invalidates pending delivery. The right-click setting never changes remote-mouse routing: while a remote application owns mouse reports, secondary clicks stay remote and the local override stays visible. Ctrl+wheel adjusts terminal font size within the readable type policy; it never shrinks text to fit a pane.

RDP/VNC and separate X11 windows normally deliver right-click to the remote application while their surface owns input. Their local session controls and capture-release action stay independently reachable; a remote context menu must not trigger a local terminal paste. Release held remote buttons/modifiers on focus loss, disconnect and capture release. A remote GUI clipboard or file-drop feature needs its own protocol capability and permission policy; ordinary terminal copy support does not qualify it.

### Default pointer model (amended 2026-10-16)

The [workspace home revision](2026-10-16-workspace-home-revision.md) adopts [MobaXterm's terminal behavior](https://mobaxterm.mobatek.net/documentation.html) (R03, rechecked 2026-10-16) as the input-default reference:

| Behavior | Default | Configuration |
| --- | --- | --- |
| Copy-on-select | On; immediate visible selection feedback; never modifies terminal content | Fixed contract default |
| Right-click | Explicit paste | Persisted per-app setting switches to local context menu |
| Shift+Insert paste | On | Fixed contract default |
| Ctrl+Shift+C / Ctrl+Shift+V | Copy selection / explicit paste | Unchanged |
| Ctrl+wheel font zoom | On, within the readable type policy | Fixed contract default |

The toggle changes only the local right-click meaning. Paste safeguards, remote-mouse routing, IME composition, OS-reserved chords and one-recipient focus ownership are unchanged. The setting is per-app and non-secret; it carries no session, trust or credential authority.

## Clipboard and paste lifecycle

The native app owns Android clipboard access. Read only for an explicit paste action in the focused recipient, and write only for explicit copy or a separately approved remote clipboard policy. Use bounded clipboard requests/results in a terminal-specific adapter; do not expose a general clipboard or credential bridge to renderer content. Clipboard text, previews and selected terminal text must not enter logs, analytics, saved state or diagnostic inventories. The system clipboard is shared system state, not private storage. [Android copy/paste guide](https://developer.android.com/develop/ui/views/touch-and-input/copy-paste), [ClipboardManager](https://developer.android.com/reference/android/content/ClipboardManager).

A missing, unavailable or unsupported clip produces a clear local state and sends nothing. Do not monitor the clipboard in a background service or poll while unfocused. Drop pending clipboard material after delivery, cancellation, attachment loss or process recreation; do not replay it on reconnect. Mark deliberately copied sensitive material with `ClipDescription.EXTRA_IS_SENSITIVE` where available, without promising secrecy from the system clipboard. Any optional timed clearing must avoid clearing a newer clip copied by another app and cannot claim secure erasure. Remote OSC clipboard reads remain denied by default; writes require the existing explicit per-host/session policy. The diagnostic's consumed OSC handlers are not product authorization.

Paste targets the visibly focused pane and captured attachment identity. A tab switch, disconnected session or changed target invalidates pending delivery. Plain text enters through the renderer's paste API, preserving its supported bracketed-paste behavior; it must not be synthesized into fake physical key presses. Bracketed paste is negotiated terminal behavior and does not make arbitrary shell text safe. Do not append an Enter. Multiline paste follows the visible configured policy from Console C05/C11. The proposed default for line breaks, trailing newline or consequential controls is a bounded preview with Insert/Cancel or the local composer; an explicitly configured direct-paste mode remains possible. Explain that a newline can execute commands in an unprotected remote shell, including when Cloudy itself appends no Enter. Do not silently strip meaningful newlines, truncate or partially send an oversized paste. Binary/image/file clipboard items follow the attachment path rather than being coerced into terminal keystrokes.
